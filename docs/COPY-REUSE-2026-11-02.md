# 完整透视表复制与分析文件复用

## 使用方式

1. 在表格工具栏点击「复制完整透视表」（手机显示「复制」），再粘贴到 Excel。
2. 点击顶栏「保存与复用」→「保存分析文件」，下载 `.pivotstudio.json`。
3. 后续点击「打开分析文件」，恢复数据、行列、指标、筛选、计算方式及图表/表格展示设置。
4. 点击「用新数据复用当前配置」，或在已保存/打开的分析中直接上传新数据。预览确认字段匹配后点击「使用原配置导入数据」。

文件只下载到本机；分享链接仍只含配置，不携带数据。分析文件本身包含原始记录，分享文件前应自行确认接收对象。

## 行为契约

- 复制基于完整计算结果，不依赖虚拟滚动区或当前单元格选区。包含表头、所有结果行、当前折叠/小计状态及总计；多层列表头展开为包含完整路径的列名。
- 优先写入 HTML 表格和 TSV；数值保持未舍入的底层值，文本 ID 保持文本。Excel 数字格式元数据用于呈现单位、精度和百分比。HTML 与公式样式文本经过转义。
- 浏览器不支持富文本写入时尝试纯文本表格，并明确告知格式限制；权限拒绝时提示失败及 Excel 导出替代路径。
- 文件格式为 `kind: pivotstudio-analysis`、`version: 1`，包含字段元数据、标量记录、经过现有白名单投影的完整配置。不通过分享 URL 编码，因此不受链接长度上限限制。
- 新数据按字段名称、类型、百分比语义及已声明单位匹配全部原字段；行数、字段顺序和额外字段不影响复用。缺少字段、类型或单位冲突时禁止直接复用，并保留原数据与结果。可显式选择「新建分析」。
- 没有保存或打开过分析文件的普通导入路径保留原有行为；现有本机配置快照和配置分享继续可用。

## 验收证据

测试全部使用合成通用字段 `Group / Period / Reading / RecordId`，不含用户交易样本。

- 手动配置 100 行：Group 行、Period 列、Reading 求和、筛选 Group=A。总计 2,500。
- 保存并重新打开文件：100 行数据与全部配置恢复，总计仍为 2,500。
- 上传列顺序反转的 1000 行：配置不变，筛选后 500 行，总计正确更新为 250,000。
- 缺失 Reading 或将其改为文本：明确报错、禁用复用按钮，原结果保留。
- 逻辑测试另验证表达式指标 `SUM([Reading])*2` 随行数变化正确重算，以及未用于分析的源字段缺失仍可检出。
- Chromium 真实系统剪贴板读回：240 个分组、表头和总计共 242 行；19 位 ID 仍为文本，数值总计为 28,920。另以工作簿解析器验证小数 1.2345 未因显示精度变成文本或舍入值。

### 已修复的实测问题与验证边界

初始 HTML 复制把已格式化文字当作单元格内容，可能使数值被识别为文本；已改为完整数值与独立格式元数据。复制入口最初位于折叠选项中，已移至默认可见工具栏。后续无障碍回归发现可见按钮文字与可访问名称不一致，已统一后重跑原检查。失败日志 `regression.txt` 保留，未删除断言来获取通过。

WebKit 测试环境的真实剪贴板写入被拒绝（NotAllowedError），因此成功复制用例在该项目明确跳过；另以真实拒绝状态验证失败提示与原结果保持。Chromium 成功读回不等同于已经验证所有系统版本的 Excel。尚未运行桌面 Excel 实际粘贴，也未开展真实用户研究。
