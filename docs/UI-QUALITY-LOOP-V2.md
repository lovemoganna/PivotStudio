# UI Quality Loop V2 · 本地优化与验收

日期：2026-10-21。基线：`63b1e25`。保留 React / Vite / Recharts、Monokai 配色、浏览器本地数据处理、现有布局和核心任务路径。未提交或推送远程。

## 基线与产品范围

主要任务是导入本地表格、调整维度与聚合、筛选结果、联动图表、查看明细，以及保存和导出视图。先执行真实产品，再审查源码。基线 35/35 Node 测试、26/26 Chromium 测试与生产构建通过。四种宽度的首页、明暗工作台和文件预览 axe 检查均无违规，文档横向溢出为 0。

测试中的内置零售数据和两行 CSV 均明确属于演示或合成机制验证数据，没有冒充真实业务结论。没有修改业务数据、聚合公式、技术栈或图表系列配色。Product Design 的 audit 流程用于截图取证；UI/UX Pro Max 的反馈与空状态指南作为辅助检查。

## 第二轮：反向检查与同类缺陷

| 问题 | 优先级与影响 | 证据和根因 | 修复及验收 |

## 第三轮：启动时快速导入

P1：Windows WebKit 下出现文件已选却没有预览。独立重复复现中，第 3 次失败：613ms 发生文件选择，615ms 创建导入 Worker，618ms 被组件的挂载清理取消；堆栈指向 React StrictMode 的 effect replay。不是解析失败、网络失败或假数据回退。

资源清理现在记录生命周期代次，排入微任务后确认没有同轮替代挂载，再终止 Worker 和导入任务。保留真正卸载的清理，以及用户取消、任务替换的立即终止行为。修复后同一诊断连续 15/15 次快速导入成功；新增浏览器回归连续执行 5 次“页面出现立即选文件”。证据见 `webkit-race-before-summary.json` 与 `webkit-race-after.json`。

## 实际验证结果

最终代码：Node **37/37**，Chromium **36/36**，Windows WebKit **36/36**；两个浏览器均无失败、无跳过、无重试。生产构建通过，`git diff --check` 无问题。

生产构建另在 360px 触屏模拟、1440px 桌面执行完整 CSV 导入→筛选 2/3 行→图表下钻→CSV 下载，均得到合计 30；无页面异常、无非 GET/HEAD 请求、无文档横向溢出。证据为 `production-smoke.json` 和对应截图。10 万行聚合切换的浏览器输入到绘制测量：Chromium 101–123ms，WebKit 178–525ms，均满足现有测试 1000ms 预算；50 万行导入取消测试也均通过。这些是本机测试结果，不是生产性能保证。

四种宽度 360 / 768 / 1280 / 1440 CSS px：首页、明暗工作台、导入预览合计 16 个 axe 状态检查均无违规；工作台 8 个明暗/宽度组合无页面异常、文档横向溢出为 0。新增筛选测试另验四宽度弹窗几何、键盘、空状态和 axe；分组测试另验 360×450 短视口。原有 R1–R8 与质量回归全部保留并通过。

复查保留了早期混合运行 **52 通过 / 3 失败 / 15 未运行** 的原始结果 `browser-results.json`，以及后续失败记录；最终通过记录为 `chromium-final-2.json`、`webkit-final-2.json`，汇总为 `verification-summary.json`。没有把未运行项目计为通过。

检查路径：

1. 首页 → 键盘文件选择 → 长字段预览：检查命名、键盘与焦点。
2. 文件导入 → Worker 解析/计算 → 分组：检查 GBK、分隔符、类型校准、Excel 日期/百分比/文本标识符、50 万行取消与内存保护。
3. 筛选 → 零行 → 恢复：检查取消最后一项、搜索、等待/失败、快捷切片、撤销/重做和配置分享恢复。
4. 表格 → 图表 → 下钻：检查真实联动、四种图表、明细与多视口布局。
5. 工作区 → 保存/分享/导出：检查本地存储恢复、配置不夹带原始记录、全量筛选排序后的 CSV/XLSX、PNG/SVG 下载。

## 性能与前后差异

同机基线引擎与候选引擎交替执行，预热各 2 次，测量各 9 次；明确合成的 10 万行数据。全部记录中位耗时 45.35→45.61ms；单区域筛选 16.76→15.64ms。差异不作为提速结论，没有看到明显计算性能退化。数据见交付目录 `performance.json`。

生产包主入口 gzip 199.80→200.50kB，CSS gzip 10.08→10.11kB，新增状态、文案和反馈带来约 0.7kB 主入口开销。没有新增依赖。四宽度基线与候选截图使用同机字体、相同演示数据、关闭远程字体和减少动态效果；遥测毫秒数字不用于像素差异判定。

关键差异：取消全部从“显示全部”变为“返回零行”；筛选弹窗内部溢出 65→0px；分组弹窗 43→0px。截图与 axe JSON 保存在交付目录 `evidence/before/`、`evidence/after/`，对照入口为 `comparison.html`。

## 限制、保留项与停止条件

不宣称获奖级或完整 WCAG 2.2 AA 合规。axe、键盘与几何检查不能代替真实屏幕阅读器、物理触屏设备、浏览器 200% 缩放与长期交互测试，这些项目未验证。未访问用户私有数据，也未对真实 Google Sheets 权限/CORS、在线发布或服务端功能作新验证。数据库连接、协作与私有 OAuth 是项目已明示未实现的能力，本轮不扩充。

首次 WebKit 执行因缺少浏览器二进制未启动，安装官方二进制后继续。完整混合回归出现文件预览超时，经过进一步重复诊断定位并修复上述实际生命周期问题；保留失败痕迹，不把首次超时当通过。延迟/失败测试遇到开发模式双次执行消费单次故障注入的问题，改为明确解除故障后再重开；深色 axe 读取时遇到禁用态正在切换的中间画面，改为等待控件结束加载、启用且不透明，再进行采样。没有为通过测试关闭 axe 规则或改用假成功数据。

依赖扫描报告现有 10 项问题（7 high、3 moderate），包括 xlsx；详见交付目录 `dependency-audit.json`。没有盲目执行强制升级。这是需要单独评估的既存依赖风险，不代表本轮做过安全审计。

本次停止原因：已取证并纳入范围的 P0、P1、P2 问题得到修复；最终完整回归无新增失败，视觉与核心任务复评未再发现本次范围内需要修复的重大短板。保留原有已通过的设计和交互，不继续做无证据的审美微调。下一项有实质价值的工作是独立评估既存依赖风险，以及真实设备、屏幕阅读器和缩放验收。
