# PivotStudio 指标模板可信度优化 · 2026-10-26

## 1. 目标理解与边界

帮助初学者理解“选了哪些字段、实际怎么算、结果能说明什么”，避免自动模板替用户作出错误的业务判断。这比新增视觉装饰或更多推荐更有价值。本轮保持现有工作台、四区配置、公式引擎、筛选、数据导入导出及历史操作机制。

工作分支：`codex/quality-manual-controls-2026-10-26`。起点为原分支 `ux/quality-loop-2026-10-25` 的现有工作区；保留其未提交内容。没有合并、推送或发布。此前的结果口径、乘法提醒、解释换行和筛选对比度修复属于上一轮，不计入本轮成果。

## 2. 本轮实际发现

先阅读已有品质报告和源码，再使用真实浏览器打开当前产品，并点击内置、明确标注的零售演示数据。没有使用外部产品作品或虚构用户研究作为证据。

| 优先级 | 位置与复现 | 影响与根因 | 本轮处理 |
|---|---|---|---|
| P1 | 指标中心→新建→毛利率：出现 `(销售大区-成本)/销售大区`；实际点击后试算为 `-` | 原匹配器在所有字段中取第一个含“销售”的名字，将分类字段作为金额求和 | 从数值度量中选择唯一、明确匹配的收入与成本候选；歧义时不推荐该组合 |
| P1 | 同一页面出现“客单价（销售大区÷去重客户类型）” | 客户类型的唯一值数量不是客户数；名称和货币格式给出了源码无法确认的业务含义 | 不再猜测客单价和订单转化率；保留通用的按记录/字段唯一值分摊模板与手动公式能力 |
| P1 | 任意前两项数值字段（样例为销售额、销量）被生成“净率”和“净额” | 数值类型和字段顺序无法证明单位兼容，更无法证明利润定义 | 改为差额比、差值和比值，说明单位与统计范围需核对；不声称比值就是占比 |
| P2 | 任意首项指标均生成“万元折算” | 未知币种、数量或其他单位被误称为人民币金额 | 改为 `÷10000` 数量级折算，不自动套用人民币 |

辅助检查：界面文字与无障碍名称存在不一致；本轮冻结的改动前版本也实际复现了该 axe 失败。没有将其作为本轮已解决项。

## 3. 最小实现及风险

- `src/utils/metricPresets.js`：集中生成计算模板。复用原有字段语义规则，排除编号、比率及默认应取平均的字段参与求和模板；匹配歧义时保留手动选择。
- `src/features/pivot/components/MetricCenterPanel.jsx`：接入共享模板规则、使用中性的计算名称；提供简短的口径核对提醒。长模板允许换行，直接上表按钮补充具体指标名称；原手动编辑器计算默认值保持不变。
- `src/i18n.js`：补充本轮静态界面文案的英文映射。动态公式说明仍主要沿用中文，不宣称完整双语校准。
- `tests/metricPresets.test.js`、`tests/browser/preset-trust.spec.js`、`tests/browser/preset-boundaries.spec.js`：增加字段误匹配、语义歧义、长字段、无安全模板时的手动编辑，以及真实导入/计算/筛选/撤销/导出验证。
- `tests/browser/quality.spec.js`：只同步“复合净率”改名为“差额比”的定位文字，保留原工作流与结果断言。

保留：先查看再提交和直接上表两条路径、手动四区配置、公式编辑、只读限制、指标库、已有指标 ID、历史配置和计算引擎。没有自动重写历史保存指标；此前保存的错误业务名称仍需核对。

主要风险：保守匹配会减少某些数据集的自动建议，用户仍可手动配置；通用差值模板不证明两项单位相同，需在使用前核对。新模板没有替代真实业务口径定义。

本轮专属差异与原始日志位于 `artifacts/quality-2026-10-26/`。`inherited.patch` 保存开始时已有的跟踪文件差异；`this-round.patch` 相对冻结的本轮起点生成，避免混入上一轮成果。因已有修改与本轮共用文件，保留为分支中的未提交修改，没有把他人的已有工作一起提交。

## 4. 操作路径与可复核证据

1. **开始与加载数据：可用。** 首屏保留文件导入、粘贴和示例入口。`01-before-workbench.png` 为导入示例后的原工作台。
2. **发现并查看模板：修复了错误口径。** 同一零售样例、同一指标编辑流程，优化前误选销售大区，优化后使用销售额与成本，试算为 **40.0%**。
3. **手动配置、筛选及理解结果：专项通过。** 明确标注的 CSV 测试数据为销售额 `100/200/100`、成本 `60/100/90`，总体差额比 **37.5%**，华东分组 **46.7%**；筛选、撤销、重做分别得到 `46.7% → 37.5% → 46.7%`。
4. **导出：专项通过。** 读取实际下载的 XLSX，筛选后总计为 **46.7%**，与表内一致。没有用“发生下载事件”代替内容验证。
5. **直接上表：真实浏览器已检查。** 内置零售样例的两年结果为 `39.6% / 41.1%`，总体 **40.0%**；口径说明包含自定义公式，未修改原行列分组。
