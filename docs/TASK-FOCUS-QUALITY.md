# 配置区、文件预览与首页专项修复

本轮按用户反馈修正三处实际使用问题。此前检查覆盖了文档溢出和部分可访问性，但没有充分检验配置字段名的可见宽度、文件预览的信息组织和首页任务聚焦；不能沿用此前“无重大短板”的结论。

## 1. 透视结构放置区：完整看清所选字段

**P1。** 原来每个区域只有半个侧栏宽度，字段名和按钮并排，名称上限 55px。实际长字段案例：360px 视口下名称只剩 24px；768、1280、1440px 下被按钮挤到 0px。两个已选行维度的完整名称都无法辨认。

修复：区域改为整行排列，每个已选字段的名称独占第一行、可完整换行，操作放第二行；字段名至少 12px，区域内小控件提升至 11px。字段列表和配置区在桌面分别滚动，不再让选中项增长挤走字段目录。保留原有区域顺序、拖拽、排序、分组、筛选、聚合、计算、移除和撤销行为。

前后几何证据：同一名称从可见 0–24px 恢复到完整文本宽度 132/144px；四种宽度下 `scrollWidth === clientWidth`，无省略号。新增回归同时放入 8 个配置项，验证完整字段名、顺序调整、平均值切换和移除；原有四区域拖拽测试继续执行。

## 2. 文件解析预览：文件、工作表、列与数据一一对应

**P1。** 原标题将说明和文件名混在一起；多工作表用拥挤的分页按钮；字段类型卡片和数据表分别展示，列头又被压成极窄列，导致读不清名称和数值。

修复：标题简化为“导入数据”，文件名作为独立的 16px 内容显示。工作表有独立选择控件和完整名称，行数、字段数与抽样范围单独说明。类型选择放回对应数据列的列头，移除重复的字段卡片。预览数据采用 14px 字号和可读列宽，宽表在自己的区域横向滚动；表头固定，内容可纵向滚动，确认按钮保留在底部。CSV 的编码、分隔符和表头校准仍直接可用。

验收使用明确合成的长文件名、多工作表 XLSX。切换到第二张表后数据与字段随之切换；第一张表的类型覆盖仍被保留；确认导入第二张表后实际透视值为 25。CSV/GBK、Excel 日期、百分比、文本标识符和金额导出继续由原有测试验证。

## 3. 首页：专注开始分析

**P2。** 原首页包含架构介绍、内存和 Worker 宣传、压测、自检、诊断状态等大量非任务内容，主要导入入口被淹没。

修复：首页保留一句用途说明、文件导入/拖放、剪贴板粘贴、示例入口和必要的本地处理说明。其他示例默认折叠；内部架构、压测与诊断宣传移出首页。相关压测和自检能力仍可通过既有工具栏/数据源入口使用，不新增假入口。移动端的导入和加载示例按钮位于首屏；默认主内容文字少于 300 字符。

## 修复中的反向检查

第一轮完整回归发现，整行配置项增加高度后，侧栏滚动会影响原有拖拽定位：Excel 导出案例拖到了相邻指标，金额断言失败。改为桌面配置区独立滚动后，四区域拖拽、金额 CSV/XLSX 和重复区域拒绝操作通过复测。

额外尝试把行维度调整到最前面时，跨区拖拽回归再次失败；已撤销这项非必要顺序变更，保留原有顺序。最终检查以修复后的实际拖拽结果为准，没有放宽金额、顺序或数据断言。

新增专项测试的首轮还发现“工作表”区域与选择控件同名造成定位歧义，已移除多余区域名称，保留选择控件的明确标签。失败记录未被计为通过。
