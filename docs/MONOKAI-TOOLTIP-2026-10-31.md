# Monokai 图表与悬浮阅读修复 — 2026-10-31

本记录取代上一轮中等明度色板方案。用户明确要求恢复 Monokai 主题色；本轮保留 Monokai 的粉、绿、青、橙、紫、黄，修复悬浮信息的阅读障碍。

## 已复现的根因

用任意导入的 Group / Reading 数据，在浅色、深色下悬浮第一根柱体。两次真实浏览器检查均得到提示卡 `backgroundColor: rgba(0, 0, 0, 0)`。现有 `bg-[#FFFDF7]/96` 和 `bg-[#1E1F1C]/96` 没有生成可用背景，背景虚化又把图形带进提示卡；默认灰色 cursor 同时覆盖整列。截图已保存并打开：

- `artifacts/monokai-tooltip-2026-10-31/before/`：浅/深主题截图及失败 trace。
- `before.txt`：2 项测试真实失败，断言是提示卡必须具有指定的不透明背景。

## 最小修复

- `pivotConstants.js` / `chartVisual.js`：恢复经典 Monokai 分类色、正负值、参考线和热力图语义色；保留实色填充与根据底色自动选取内部黑白文字。
- 明亮填充在浅色纸面上增加 0.75px 墨色轮廓，保留色相。中性图例文字及参考线说明保持清楚。
- `UnifiedChartTooltip.jsx`：使用不透明暖白/深黑卡片，移除背景虚化；保留主题适配的文字墨色；增加行高、限制视口内宽度，名称可换行，数值不挤缩。
- 普通系列提示中的色标从系列元信息取得，避免把 `url(#gradient)` 当作 CSS 背景颜色而丢失色标。
- `ChartStudio.jsx`：共享低透明度的悬浮区，替代遮盖图形的默认灰块；所有使用统一 Tooltip 的图表路径采用同一修复。
- 未修改计算、筛选、百分比口径或图表配置数据。

## 检查步骤

1. 浅/深主题柱图悬浮：修复后两种浏览器检查背景确实不透明，标题、数据、样本说明、占比及均值差可读。`after/` 截图已与 `before/` 对照打开检查。
2. 代表视口：360 / 768 / 1440；检查提示卡不超出水平视口，色标存在，悬浮区透明度为 0.045。
3. 桌面不同图形：折线、饼图、瀑布、直方图、散点，真实鼠标悬浮后检查提示卡底色与 WCAG A/AA 自动扫描。
4. 共享图表回归：导入八系列任意字段、标签位置及显隐、正负零值、两种主题、SVG 和 CSV 下载。

## 验证标准的调整

原测试要求所有填充在浅色纸面至少 3:1，与用户指定的明亮 Monokai 色本身冲突。因此改为验证经典色值准确、明亮填充在深色纸面至少 3:1，以及浅色填充所用墨色轮廓对纸面至少 3:1。内部数值文字和透明热力图合成后的文字仍要求至少 4.5:1，未降低此标准。此边界并不声称所有浅色细折线或所有色觉条件均已满足可辨识性要求。

## 保留边界

没有真实用户研究或屏幕阅读器人工验证，不将自动检查当作用户体验研究。上一轮发现的多系列窄屏标签重叠尚未解决。本轮未发布线上。

## 第二次修复：实际绘图区约束

第一次扩展矩阵在 360px 浅色主题真实失败：卡片右边界为 375.61px，超出 360px，且被图表容器裁切（`verification.txt` / `verification/`）。保留了原断言，未放宽视口限制。

使用 Recharts 传给提示内容的实际 `viewBox.width` 限制卡片宽度，取消悬浮位置动画。卡片的可用宽度跟随绘图区而非单纯跟随窗口，因此侧边栏、窄屏、分栏和全屏布局都使用同一约束；数值与名称仍来自同一原始 tooltip payload。

## 第三次修复：饼图标签不拦截鼠标

`recheck.txt` 的桌面跨图表测试停在饼图：真实 hover 调用报告数值标签文字拦截目标扇区的鼠标事件。为两个饼图说明层设置 `pointerEvents="none"`，使鼠标实际落到扇区；保持原来的悬浮测试和所有可见标签，不使用强制 hover 绕过问题。最终复测改用静态生产构建，以核对实际交付样式。

源码修复到此共三轮。最终预览为 `http://127.0.0.1:5218/?demo=retail`；预览选择 Monokai 深色主题，产品默认主题偏好未更改。`preview.png` 是最终构建的实际浏览器截图，已打开检查。

截图复核：最终构建的 360px 浅色悬浮卡（`hover-mobile-light.png`）与 1440px 深色悬浮卡（`hover-dark.png`）均已打开检查，标题、值、样本说明和百分比完整可见。它们是从 `final/` 原始截图直接复制的相同字节，没有合成或重绘。先前修复过程中的截图不作为最终外观证明。

## 最终矩阵的测试定位校正

生产构建矩阵先通过 32 项，在 WebKit 桌面折线悬浮的自动定位步骤超时，另一项未运行（`final.txt` / `final.json`）。trace 显示移动鼠标已经激活了更大的活动圆点，它覆盖普通圆点，导致定位器持续等待普通圆点“接收事件”。这不需要禁用活动点或改动其点击功能。

仅修正该测试的鼠标路径：读取已可见普通点的边界，真实移动鼠标到该点中心，继续断言 Alpha 提示内容、不透明背景及全部 WCAG A/AA 规则；不使用强制 hover 或删减断言。桌面浅深主题在两个浏览器上单独复测，日志为 `desktop.txt` / `desktop.json`，不重复修改产品源码。
