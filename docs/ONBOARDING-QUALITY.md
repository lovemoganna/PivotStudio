# 入门分析路径品质修复 · 2026-10-21

本轮以首次导入、自主添加指标、分组计数、切换计算口径及撤销为范围。保留现有架构、数据和视觉语言；没有重新扩写首页，也没有接入演示数据替代用户数据。

## 证据与修复

|优先级|复现与影响|根因及修改|验收|
|---|---|---|---|
|P0 结果误导|导入转化率 0.1、0.3、0.5，仅导入后手动添加指标。原界面显示“求和 1”，而自动推荐为均值。新用户难以发现计算口径已改变。|自动推荐和手动添加分别生成默认配置。提取共享 `getMeasureDefaults`，统一比率、年龄等均值字段的起始聚合及格式。|四种宽度真实运行，结果一致为均值 30.0%；可显式切换口径并撤销。该值是未加权算术平均。|
|P0 单位误导|百分比或金额指标切换到计数后，原字段的百分比、货币、小数设置仍应用到计数；Excel 导出也会保留错误格式。|显示格式没有优先识别计数。表格、图表、CSV 和 Excel 统一把普通计数显示为整数记录数；计数的百分比占比仍按百分比显示。|格式单元测试；真实浏览器切换、撤销及下载 XLSX 后读取显示值；确认 3 笔，不是 300% 或 ¥3。|
|P0 总体口径误导|华东两条记录均值 20%，华南一条记录均值 50%，总体应为 30%；原底栏显示“总和 70%、均值 35%”。|底栏把图中分组结果再次相加/平均，误当作总体。改为读取原始记录聚合出的总体指标卡结果；均值、去重计数等不可加指标悬停时也不再宣称占总体比例。|保存真实前后截图与底栏文本；分组值仍为 20%/50%，总体及底栏统一为 30%。|
|P1 入门路径中断|“仅导入数据”后没有指标，缺少下一步操作。纯文本数据没有数值字段，新用户无法直接统计每类记录数。|缺少空状态行动入口。提供“统计记录数”，保留分组和筛选，纳入原有撤销历史。|三行文本表先显示 3 笔，按地区分为 2/1 笔；保留华东筛选时只计算 2 笔；撤销恢复前一配置。|
|P1 键盘入口缺失|工作区上传 input 为 display:none，不能通过键盘到达；重复 +行/+值按钮缺少字段上下文。|上传 input 改为视觉隐藏但可聚焦；添加按钮包含字段名和用途，保留原鼠标、拖拽路径。|键盘聚焦、Enter 添加字段；生产环境 Enter 实际唤起文件选择并再次导入。|
|P2 术语与空区域无法指导操作|四个放置区只写“拖拽至此”，没有说明分组、比较、计算、筛选的作用。|空区域改为简短任务提示；可展开的帮助解释行列值、按钮替代拖拽、算术平均与业务加权比率的区别。记录数在主要界面和导出中使用可理解名称。|360/768/1280/1440 下检查布局、键盘帮助、无障碍与原有字段操作。|
|P2 小样本计数图重复刻度|分组计数只有 1/2 条记录时，坐标轴自动生成小数刻度，再按整数计数显示为多个相同的“2 笔”。|计数轴只生成整数刻度；百分比模式仍允许小数。|默认柱状及折线、面积、堆叠、横向条形、双轴和瀑布图逐项检查刻度不重复。|

## 限制与停止原则

字段名称只能给出起始建议，不能推断加权业务比率的分母或数据所代表的真实业务。未验证真人新手的任务成功率、真实屏幕阅读器、所有语言与所有数据分布；自动 axe 检查不能替代完整 WCAG 认证。本轮不会据此宣称产品已经全面成熟或达到奖项标准。

下一轮最值得验证的是：让用户辨认有效样本、缺失值和计算分母，并通过真实新手任务观察检验指引是否有效。只有获得足够证据才扩大实现范围。

- 完整 Chromium + WebKit 回归 102/102，无失败、跳过或重试掩盖。

- 生产构建成功；主包 gzip 从上轮 198.70KB 到本轮 200.34KB，微幅增长；没有新增依赖。Worker 为 26.61KB，避免将整份翻译字典带入 Worker。
- 生产环境实际键盘唤起文件选择、二次导入、均值/计数切换、XLSX 下载并读取格式均通过。
- R1 50万行导入与 R3 10万行刷新性能检查继续通过；测量受机器负载影响，原始结果在 test-summary.json，未宣称速度提升。
- 中间失败已定位：测试需区分正文与总计单元格、总体栏与悬停反馈；整数刻度允许自动留白产生负数。修正测试前提后重新执行，原始失败输出予以保留。

停止原因：本轮有直接证据的口径误导与入门路径断点已修复；进一步引导设计需要真人任务观察与数据质量证据，继续凭主观判断增加说明会违背简洁目标。已知未覆盖范围如前述限制。
