# 窄柱数值标签优化（2026-11-06）

## 目标与证据

用户希望直接看到柱子上的值。现有显示开关默认开启，但自动标签绘制函数会直接丢弃宽度小于 18px 的竖柱，以及部分较短负柱。这与分组柱图的实际空间不符：稀疏多系列里，单柱虽窄，周围可能有充足空白。

使用上一轮仅供本地测试的真实工作表重现：同一桌面页有 8 个有效数值，修改前标签数为 0，修改后为 8。手机和平板当前页分别显示 3 个有效数值。原始数据、截图和下载文件位于被 Git 忽略的 `artifacts/bar-labels-2026-11-06/`，不随代码提交。

## 最小修改

- 自动标签不再仅因柱宽小而隐藏。数值使用已有紧凑格式；标签略增至 10px，并为外部标签添加与背景一致的描边，改善网格线、柱色背景上的阅读。
- 同组相邻系列空间不足时按标签宽度和柱宽错位排列；顶端空间不足时向绘图区内回落。负值、真实零值和横向条形保留标签。
- 手动位置计算和显示开关保持不变，不自动覆盖用户设置。
- 分组柱图在格式化前检查原始值，缺失或不可计算的值不生成标签，避免空值被格式化为横线或被百分比转换误标为零。
- 本轮只修改标签显示，不修改聚合、筛选、排序、分页和坐标范围。

## 验证

- `npm test`：160 项通过。新布局测试覆盖窄柱、零值、短负值、等高系列错位、边缘位置及非法几何输入。
- 生产构建通过。
- Chromium / WebKit：原有标签位置与开关测试在 360 / 768 / 1440 视口通过；全部图表家族和正负值位置测试通过。
- 新增窄柱测试在两浏览器的手机、桌面通过：所有有效值与零可见，空位不标值，SVG 保留标签，关闭开关后标签消失。
- 新增手机等高五系列测试在两浏览器通过：20 个标签全部显示，实际文本矩形没有相交。
- 首轮新测试在两个浏览器桌面失败，是测试在 ResizeObserver 布局稳定前缓存了 3 个类别，而最终页面已经变为 8 个类别。改为轮询当前类别数与当前标签数一致，保留原断言目标；6 项新回归最终全部通过。日志保留初次失败。
- 真实数据 Chromium 1440 浅色、768 深色、360 浅色检查：当前页标签分别为 8 / 3 / 3，均未超出 SVG 边界，PNG 实际下载成功，SVG 标签数量与界面一致；已查看桌面导出图。

## 说明

紧凑标签沿用原有数值格式；精确金额仍通过悬浮提示和表格查看。错位是针对空间的自动排布，没有证明任意长单位、任意系列组合都不会产生重叠，已有手动位置入口继续保留。本轮没有真实用户研究，不以自动化检查替代用户阅读体验判断。
