# 窄屏手动分析路径优化 · 2026-10-26

## 目标与边界

落实上一轮获批准的方向：用户不用推荐模板，也能找到行、列、值、筛选，通过键盘独立配置透视表；面板变窄时仍能看见字段并修改指标。

继续使用 `codex/quality-manual-controls-2026-10-26`。保留进入本轮时的全部修改，包括上一轮模板可信度修复，没有合并、发布或重写历史保存配置。计算、导入导出、筛选与历史机制未修改。本轮实现和测试证据单独存放，避免把上一轮成果重复计算。

## 真实发现与最小修复

| 问题 | 真实证据 | 改动与验收 |
|---|---|---|
| 字段选择器在窄面板中不可读 | 768px 浏览器、292px 指标面板，字段选择器仅 **24px**；实际截图中只剩箭头。根因是按整个浏览器的 `sm` 断点分三列 | 使用面板容器查询。窄面板纵向排列，600px 以上才并排。相同视口和指标下字段选择器约 **154px**，字段名完整可见 |
| KPI 和指标库仍按视口分列 | 源码中的 KPI、目录和编辑网格共用相同的错误宽度假设 | 统一按面板宽度分列，保留原有卡片和编辑功能；验证 1280px 屏幕上键盘将侧栏扩到 680px 的真实窄面板场景 |
| 试算区被数值变化撑宽 | 导入验证 CSV，首项选 Revenue，使试算变为 100.0% 时，真实浏览器测得约 10px 内部溢出；专项自动化测得 7px | 试算容器和结果允许换行。相同数据及操作后内部溢出为 **0**；保留完整试算值、公式提示与提交操作 |
| 可见文字与无障碍名称不一致 | 原界面可见 `+值`、`+筛`、`指令 ⌘K`、`指标中心 2`，读出的名称缺少对应内容 | 字段快捷入口包含可见短标签和具体字段；指令名称包含快捷键；指标中心名称包含可见数量。仍有明确字段上下文，既有键盘行为保留 |
| 布局调节控件在页面区域之外 | 上一轮实际失败记录及本轮结构检查指向侧栏宽度分隔条 | 仅为布局调节区域增加具名区域，保留主内容为顶层 main、原有焦点及方向键调节 |

## 本轮操作路径

1. **导入：通过。** 使用清楚命名的 `explicit-manual-path.csv`，4 条验证记录，仅导入数据并清空透视，不调用推荐。
2. **配置四区：通过。** 键盘添加 Region 到行、Period 到列、Revenue 到值、Region 到筛选。总计 **1,000**，按 Jan/Feb 分列合计 **400/600**。
3. **改变口径：通过。** 改为平均值得到 **250**，撤销恢复 **1,000**。
4. **筛选和历史：通过。** 仅保留 East 后总计 **300**；撤销 **1,000**，重做 **300**。真实浏览器独立操作也得到相同结果。
5. **导出：通过。** 读取实际下载的 XLSX，最后一项为数值 **300**，与表格一致。
6. **窄面板指标编辑：通过。** 768/1280/1440px 场景下键盘从字段选择器进入聚合控件；配置 Revenue/记录数，试算与实际表格均为 **250.0**。1280px 场景使用分隔条的 End 键扩宽侧栏，验证面板而非视口的断点。

以上数据明确用于验证，不代表真实用户研究或外部业务数据。手机和平板为真实浏览器中的视口模拟，不等同于物理设备测试。

## 限制与下一步

没有运行实际屏幕阅读器、语音控制、物理移动设备或原生 200% 缩放；不以 axe 通过宣称完整无障碍合规。未开展真实用户研究，没有用户耗时、求助次数或成功率对照。

上一轮记录的 WebKit 分析笔记按钮对比度不稳定未在本轮扩展修复；本轮未复现的结果及原始历史记录分别保留。

**仍有一项有实际证据的高影响边界问题：** 在 768px 视口下，聚焦侧栏宽度分隔条并按 End，侧栏变为 680px，结果区只剩 **84px**。真实截图见 `08-resizer-end-boundary.png`；随后按 Enter 已恢复默认 440px。该键盘上限处理函数本轮没有修改，未对改动前版本单独运行同一边界，所以不把源码判断冒充基线浏览器验证。1280px 的键盘调整测试通过不能推断这一场景也通过。

该问题在三轮实现后额外的边界检查中发现；依照用户规定的最多三轮修复上限，本轮保留证据并停止追加产品改动。它不属于已经通过的窄面板范围，不能宣称所有键盘/窗口尺寸组合均可用。

下一轮唯一优先方向：统一鼠标拖动、键盘调整、持久化宽度及窗口变化的侧栏宽度边界，为结果区保留可用宽度。这比继续添加局部样式更能保护用户独立完成分析任务。
