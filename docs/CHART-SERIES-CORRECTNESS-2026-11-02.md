# 图表指标绑定与显示口径修复 · 2026-11-02

## 目标与现场证据

让用户选择的指标真正决定图表，且表格、图例、悬浮提示与导出能清楚区分同一字段的不同计算定义。修复共享图表机制，不加入交易、零售或某个字段名称的特殊判断。

在用户当前 `http://127.0.0.1:5221/` 页面只读检查并截图：行是对手用户 id，没有列维度；四个指标包括两个数量计数、成交金额求和、同一金额的占总计百分比。创建时间筛选保留四条交易，排除源文件已有的总计行。值选择器指向金额求和。

表格中的金额聚合正确；显示精度为零时存在格式舍入，与本次图表数据覆盖错误不同。原始测试表及其汇总数值仅保留在本地，不随代码发布。

修复前图表同时绘制四个指标，金额与占比图例同名，金额柱被百分比覆盖，均值线却按第一个计数指标显示 AVG 2。现场证据保存在忽略目录 `artifacts/chart-series-correctness-2026-11-02/before.png`。

## 根因与修改

1. `buildChartSpec.js` 使用字段名和聚合名称构造数据键，无法区分同字段、同聚合、不同显示方式的指标。改为使用指标 id 保存数据，显示名称单独管理。
2. 没有列维度时，普通图表忽略主指标选择并遍历全部指标；统计、排序、均值线读取第一个系列。普通图表现在跟随所选指标；堆叠柱、堆叠面积和百分比堆叠保留多指标机制。配置了列分组时，保留所选指标的各列系列。
3. 双轴与散点图按主、次指标定义绑定；默认次指标避开主指标。双轴选择器显示实际生效的指标，避免界面与引擎的默认次指标不一致。多行维度在这两种图中保留完整分组，而不被误当作两个指标系列。
4. `ChartStudio.jsx`、`PivotTable.jsx`、`UnifiedChartTooltip.jsx`、`exportMatrix.js` 复用已有 `describeAnalysisMeasure`。表头、选择器、图例与导出明确标出“有效值计数”“求和 · 占总计百分比”等定义，长表头保留完整标题提示。
5. 数值计算、筛选、源数据和既有格式设置不变。没有推断或写死货币单位。

普通图表现在只呈现所选指标，这是有意修正值选择器与绘图行为不一致的契约。原计数浏览器用例的三个计算预期都保留，改为分别选择指标后核对；没有删除数值、筛选、历史或导出断言。

## 当前界面仍值得优化的事项

| 优先级 | 已观察的情况 | 影响与后续方向 |
|---|---|---|
| 高 | “买入数量”的有效值计数为 4，包括三条数量为零的记录；实际买入记录为 1 | 算法正确，但非空计数不等于业务事件计数。下一轮建议增加指标各自的统计条件，让不同条件的指标能在同张透视表比较；公式引擎当前的聚合函数没有 COUNTIF / SUMIF。 |
| 高 | 本地更新触发页面刷新后，临时数据需要重新关联 | 本轮已用原始文件恢复字段、指标及时间筛选。需要明确草稿保存/恢复策略；生产环境恢复路径尚未专项验证。 |
| 中 | 金额默认显示零位小数，长表头容易截断 | 结果可能被误读为精度丢失。已有“格式与数值”可调整，应改善字段格式的初始校准与可发现性，而不是把所有数值都当货币。 |
| 中 | 少量结果仍占据很高的表格区域；长 id 倾斜显示，小值柱接近基线 | 目前标签和整段类别提示可读取数值，但图表比较效率仍有限。应改进结果区域空间分配及长类别阅读，不能通过抬高小柱伪造比例。 |

这轮验证属于开发者实际界面检查与自动化回归，没有真实新手研究，因此不宣称已测得学习成本或任务完成率改善。下一轮只优先建议条件聚合：它也适用于有效订单、成功请求、完成任务等任意数据结构，不应写成交易专属功能。草稿恢复和显示布局列为后续事项，本轮不扩大实现范围。
