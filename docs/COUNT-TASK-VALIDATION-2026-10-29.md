## 实际任务与独立预期

导入自定义 CSV，选择“仅导入数据（清空当前透视）”，不调用推荐配置或 AI。通过字段选择器用键盘添加行维度 Cohort，以及记录数、Token 有效值计数、Token 去重计数。

| 范围 | 输入 Token | 记录数 | 有效值计数 | 去重计数 |
|---|---|---:|---:|---:|
| A | X、X、空、0 | 4 | 3 | 2 |
| B | X、Y、空、纯空格 | 4 | 2 | 2 |
| 全部 | A 和 B 的原始记录 | 8 | 5 | 3 |

以上数字是人工确定的断言值，不由生产聚合函数生成预期。总体去重为 3，而不是分组去重相加的 4。

浏览器真实完成并检查：

1. 手动选择三种计算方式，同一字段可配置多个口径；逐组和总计分别核对。
2. 用键盘展开“总计怎么算”，核对空值、非空文本和重复值说明。
3. 添加 Cohort 筛选，排除 B 后为 4 / 3 / 2；撤销回到 8 / 5 / 3，重做回到 4 / 3 / 2。
4. 实际下载 XLSX，保存原文件并重新读取，核对最后三列为数值 4 / 3 / 2，且没有 B 组。
5. 修改已配置指标的计数为去重，结果变为 4 / 2 / 2；撤销恢复 4 / 3 / 2。
6. 核对图表标签为 4 / 3 / 2；记录数的聚合选择固定，防止切换到不适用口径。
7. 三种宽度检查页面没有横向溢出，axe 未发现违规；保存截图。初步通过后的三种宽度截图已实际打开查看，窄屏表格使用自身横向滚动。

补充逻辑测试用英文、中文和带空格字段名验证相同机制；覆盖 null、undefined、空字符串、纯空格、0、false、重复值及空筛选范围。false 和 0 均是有效值。

## 结论和边界

本轮未发现这三种计数的计算、筛选、历史或导出回归，因此没有为通过测试修改产品。

观察到配置卡片仍使用简写“计数 / 去重”，完整“有效值计数 / 去重计数”见结果说明；是否造成新手误选仍是待真人验证的假设。自动化选择正确选项并不证明真人能独立选对。也没有完成屏幕阅读器实测、真人触控测试或全仓所有浏览器用例。

下一步只建议让新用户在不提示术语的任务中选择这三种口径，记录首次选择、求助和纠错，再决定是否需要修改选择时的提示。
